# 平台管理员账号拆分

## 目标

- 原 `admin` 登录名、密码、教学数据全部不动，只从平台管理员恢复为纯老师；
- 新建独立平台管理员 `aren_platform`，只用于平台概览、账号和机构管理；
- 平台管理员不加入任何机构，不初始化课程、学生、成绩等业务表；
- 原教学账号标记为“受保护教学账号”，防止其所在机构被误删。

## 上线前本地备份

先完成只读云端备份。本次使用的前缀是：

`backups/manual_20261029_pre_split/database/`

备份包含 6 个文件：

- `scores.db`
- `cui/scores.db`
- `king/scores.db`
- `kun/scores.db`
- `platform.db`
- `teachers.json`

## 上线时具体改什么

### `teachers.json`

1. 找到当前唯一 `is_admin: true` 的条目；
2. 把该条目的 `is_admin` 改为 `false`，增加 `protected: true`，保留原登录名、原库标识和全部教学数据；
3. 新增 `aren_platform` 条目，设置 `is_admin: true`，使用独立库标识 `aren_platform`；
4. 在 `usernames` 增加 `aren_platform -> aren_platform`；
5. 原有 `admin` 等登录名映射不改。

### `platform.db`

不改表、不删字段、不删机构成员。

新平台管理员不写入 `org_user_roles`，以后启动时也会跳过所有 `is_admin` 条目。
原教学账号已有机构关系保持不变。

### 新平台管理员数据库

创建：

`database/aren_platform/scores.db`

其中只有账号、登录审计和说明同意相关表，不含学生、课程、成绩、试卷业务表。

## 执行顺序

1. 备份已存在并核对；
2. 下载云端 `teachers.json` 和原管理员那一份数据库到 D 盘临时目录；
3. 在临时目录执行拆分并校验；
4. 上传新平台管理员数据库；
5. 下载并比对哈希，确认新库完整；
6. 最后才更新 `teachers.json`；
7. 再下载名册，确认只有一个 `is_admin: true` 且为 `aren_platform`。

云端命令必须由用户确认后执行：

```powershell
D:\python\python.exe tools\split_platform_admin.py --apply --cloud --confirm CLOUD
```

脚本会生成一次性密码，只在成功后的本地终端显示一次；不会把明文密码写进 Git、报告或数据库。

## 回滚

拆分时会在本地生成：

```text
backups/account_split_<时间>/
├─ teachers.json
├─ platform.db
├─ old_admin/scores.db
└─ manifest.json
```

回滚顺序：

1. 用备份的 `teachers.json` 覆盖当前名册；
2. 用备份的 `platform.db` 覆盖当前平台库（本次实际上不会改它）；
3. 把新平台管理员数据库移到备份目录的 `quarantine/`，不直接删除；
4. 原教学账号重新成为平台管理员，原登录名和密码不变。

代码中的离线回滚入口：

`account_split.rollback_split(data_dir, backup_dir)`

## 忘记密码

平台管理员忘记密码时，不使用网页公开找回入口。由维护者在本地从云端读取
`database/aren_platform/scores.db`，生成新的 PBKDF2 密码哈希后上传。
原教学账号 `admin` 的密码和数据库不受影响。
