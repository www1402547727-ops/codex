# 备份还原步骤

## 备份规则

- 每次数据库保存后，系统会尝试生成当天的一份快照。
- 云端路径：
  - 老数据：`backups/日期/scores.db`
  - 其他老师：`backups/日期/老师标识/scores.db`
  - 平台账号库：`backups/日期/platform.db`
- 每天同一份数据库只写一次当天备份，避免应用重启后覆盖当天较早的状态。
- 系统保留含今天在内的 31 个自然日，更早的备份自动删除。
- 备份清理失败不会影响当次正常保存，下一次保存时会再次尝试。

## 还原前

1. 先让相关老师暂停录入。
2. 确认要还原的日期和老师标识。
3. 下载目标备份后，先复制一份到测试目录，不要直接覆盖线上文件。
4. 记录当前库的文件大小和修改时间，保留故障现场。

## 从 Supabase 下载

1. 打开 Supabase 项目 → Storage → `student-files`。
2. 进入 `backups`，选择日期目录。
3. 下载对应老师的 `scores.db`，或平台库 `platform.db`。
4. 不要把学生数据库、密码或密钥发到聊天、群聊或公开仓库。

## 测试环境演练

1. 在 `D:\gpt\workbuddy-cache\` 建一个全新目录。
2. 把下载的备份复制为 `scores.db`。
3. 用测试配置启动项目，使用备份中的老师账号登录。
4. 检查学生数、课程表、成绩和课时统计是否正常。
5. 只有测试环境确认可登录、可读取、数量正确后，才考虑正式还原。

## 正式还原

1. 先另存当前线上数据库，命名中包含“还原前”和日期。
2. 在 Supabase Storage 中把备份下载到本地。
3. 用 Streamlit Cloud 的管理入口停止应用，或选在无人使用时操作。
4. 将备份上传到该老师原来的数据库路径：
   - 老数据：`database/scores.db`
   - 其他老师：`database/老师标识/scores.db`
   - 平台账号库：`database/platform.db`
5. 重新启动应用，先登录测试账号。
6. 检查课程、学生、成绩和账号后再通知老师继续使用。

## 还原后检查

- 老师账号能登录。
- 学生账号能登录，且只能看到自己的内容。
- 课程表日期、时间、班级/一对一对象正确。
- 成绩、试卷、答题卡和分析能打开。
- 一对一剩余课时和班级月度统计正确。
- 平台审计日志仍然可读。

## 注意

- 不要用其他老师的备份覆盖当前老师的数据。
- 不要把 `platform.db` 和老师业务库互相覆盖。
- 还原完成后不要立即删除旧备份，等确认无误后再按保留期自动清理。
- 体验版每日备份不保证永不丢失，重要资料仍需自行保留原件。
